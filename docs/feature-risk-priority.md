# Feature Risk Priority

## 목적

이 문서는 현재 기능을 `안전 / 주의 / 위험`으로 구분하고, 운영 전 반드시 확인할 기능과 향후 단일화 우선순위를 정리하는 문서다.

## 운영 전 반드시 기억할 원칙

- 지금은 마이그레이션하지 않는다.
- 이번 문서화는 “정리 계획”이 아니라 “운영 잠금”이 목적이다.
- 위험 기능이라고 해서 지금 구조를 바꾸지 않는다.
- 단지 운영 전 어떤 기능을 더 조심해서 봐야 하는지 우선순위를 고정한다.

## 위험 기능

### 1. 새 메인 타임라인 블록

- 현재 `localStorage` 단독
- 다른 PC 공유 보장 없음
- 운영 전 “공유 데이터가 아님”으로 표시 필요

### 2. 갤러리

- `galleryData / galleryItems / IndexedDB / storage bucket / deleted ids / shared_state`가 함께 얽힘
- 삭제/복구 작업 위험
- 운영 전 실제 자료 위치 확인 필요

### 3. 운영메모

- `localStorage` 단독
- 다른 PC 공유 보장 없음

## 주의 기능

1. 공용일정
2. 개인일정 상세
3. 방송편성
4. 월드컵 뉴스
5. 장비
6. 문서보관
7. 파일보관
8. MAP 핀

## 상대적으로 안전한 해석

- “안전”은 구조가 단순하다는 뜻이 아니라, 현재 운영 시점에 대규모 저장 병합/복구 위험이 상대적으로 낮다는 뜻이다.
- 현재 저장 구조가 혼합되어 있으므로, 사실상 대부분 기능은 최소 `주의`로 보는 것이 안전하다.

## 운영 전 반드시 확인할 기능

1. 공용일정
2. 개인일정 상세
3. 장비
4. 방송편성
5. 월드컵 뉴스
6. 파일보관
7. 갤러리
8. MAP 핀
9. 새 메인 타임라인 블록
10. 운영메모

## 운영 중 건드리면 안 되는 기능

- 갤러리 삭제/복구 경로
- 새 메인 타임라인 블록 저장 구조
- 운영메모 저장 key
- 공용일정 fallback 정리
- 개인일정 상세 key rename
- 파일보관 bucket/table/local payload 구조

## 향후 Supabase 단일 루트로 옮길 우선순위

1. 갤러리
2. 운영메모
3. 새 메인 타임라인 블록
4. 개인일정 상세
5. 공용일정 fallback 정리
6. 문서/파일보관 fallback 정리
7. 방송편성 메모 계층 정리
8. MAP 핀 local/shared fallback 축소

## 결론

- 위험 기능은 “지금 당장 구조 변경” 대상이 아니다.
- 위험 기능은 “운영 전 반드시 사람 눈으로 확인” 대상이다.
- 다음 기능 수정 작업에서는 먼저 `docs/storage-source-of-truth.md`와 이 문서를 보고, 저장 원본이 혼합인지 단독인지 판정한 뒤 작업한다.
